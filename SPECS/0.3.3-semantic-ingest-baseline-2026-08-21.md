## Hardened Benchmark Summary

The original `10/10` run below is now treated as development-set evidence, not
as an acceptance-quality certificate. Two independent audits found that the
first fixture sources contained category-routing hints and that the scorer did
not enforce the deterministic gates described in the benchmark spec.

The benchmark was hardened in the same workstream:

- source files were de-instructed so category labels live in `expected.yaml`,
  not in `source.md`;
- `run_baseline.py --self-test` now covers negative controls for token-overlap
  false positives, concept dumps, under-split pages, silent hold no-ops, and
  seeded concept absorption;
- scorer output now includes deterministic gates for terminal status,
  manifest/source traceability, page validation, manifest validation, index
  rebuild, `type`/path consistency, idea metadata, and unknown categories;
- forbidden objects distinguish dump-page bans from specific unsupported-claim
  bans;
- the ingester skill received a minimal instruction patch for object inventory,
  lookup overproduction, and source/manifest discipline on every touched page.

Pressure scenarios that failed before the skill patch:

- `0003-query-lookup-floor`: the old skill created

- `0009-merge-magnet-seeded`: the old skill updated

## Post-Audit Hardening, 2026-08-22

Independent Sol max and Grok xhigh audits found additional benchmark leakage
and scorer permissiveness after the first `10/10` development-set run. The next
hardening pass made these changes before any new provider leaderboard claim:

- provider capture names, evidence directories, and temporary wiki paths use
  neutral case identifiers instead of semantic fixture slugs;
- remaining category-like prose was removed from several `source.md` files,
  while preserving the domain facts needed for model judgment;
- `touched_pages_cite_source` became a current `raw/source.md` gate, and raw
  manifest checks now require the current raw entry to reference every touched
  page;
- the scorer now gates malformed frontmatter, fixture-unexpected categories,
  and content pages that are not matched to any expected object;
- forbidden pages fail when newly created even if the object also has specific
  unsupported-claim checks;
- negative controls now cover negated positive claims, unrelated negation in
  forbidden claims, stale sources, malformed frontmatter, extra pages, and the
  Ambervault sibling entity overproduction case;
- `0004` now treats a cautious current Trestle entity page as optional instead
  of forbidden, `0003` explicitly forbids an Ambervault product page, and
  `0010` requires Foldgate to stay out of `concepts/`.

These changes intentionally make old `10/10` snapshots stricter under rescore.
They improve the development harness; they still do not replace a frozen
held-out challenge pack.

## P1 Audit Fixes, 2026-08-22

A follow-up Sol/Grok audit blocked a fresh provider baseline on four benchmark
P1s. The blocking fixes were:

- fact matching now evaluates lines, clauses, and adjacent-line chunks while
  preserving negation polarity, instead of requiring every claim to fit one
  physical Markdown line;
- output pages are assigned to expected objects only after a passing outcome,
  so optional or forbidden objects in the wrong category cannot hide extra
  pages from `no_unassigned_content_pages`;
- `raw/source.md` integrity now requires the raw file SHA and manifest SHA to
  match the fixture source SHA, and the manifest origin must point to the
  neutral `inbox/<case-id>/source.md` evidence path;
- provider case diagnostics are written under neutral case-id directories;
- the seeded `0009` job-queues page was made validator-clean and no longer
  contains text instructing the model not to absorb later product-specific
  facts;
- self-tests now cover `concepts/ambervault.md`,
  `entities/retry-policy.md`, `concepts/trestle-cli.md`, stale raw sources,
  missing/malformed frontmatter, and negation polarity regressions.

No fresh provider baseline was run as part of these fixes. The next step is a
read-only audit of the patched harness before spending provider quota.

## Polarity Matcher Fix, 2026-08-22

The first `0.3.6` audit still blocked the provider baseline on a matcher
regression: paragraph-level chunks could falsely match a correct compact Sable
Queue entity against the forbidden claim `Dead letters are automatic in Sable
Queue.` The fix removed whole-paragraph matching, avoids whole-line matching
when a line splits into multiple polarity-bearing clauses, and requires exact
origin path components instead of a substring match.

Self-tests now include the reversed Trestle proposal polarity, a positive
forbidden clause next to an unrelated negation, exact `origin` path checks, and
a full passing compact `0009` Sable Queue entity. No fresh provider baseline
was run as part of this matcher fix.

## Strict Forbidden-Claim Matching, 2026-08-22

The `0.3.7` audit still found two P1 scorer gaps before a new provider
baseline:

- clause splitting missed contrastive connectors such as `instead`, `while`,
  and `whereas`, so a sentence could combine a forbidden positive claim with an
  unrelated negation and still pass;
- short forbidden claims could pass on partial token overlap, so a correct
  Sable Queue sentence about opt-in dead letters could falsely violate
  `Dead letters are automatic in Sable Queue.` by omitting the central
  predicate `automatic`.

The scorer now splits those contrastive clauses and uses a stricter coverage
threshold only for `must_not` checks. Normal `must` coverage stays tolerant
enough for natural wording, while forbidden claims need stronger evidence that
the unsupported assertion itself was made.

Self-tests now include full `score_case` regressions for reversed Trestle
proposal polarity, a `Trestle check ships ... while dry-run does not typecheck`
forbidden clause, and a compact correct `0009` Sable Queue entity with
`In Sable Queue, dead letters are opt-in...` wording. No fresh provider
baseline was run as part of this matcher fix.

## Forbidden-Claim Anchor Matching, 2026-08-22

The `0.3.9` audit still blocked a provider baseline. It found that the stricter
`must_not` matcher fixed the exact earlier examples but still missed the broader
classes:

- contrastive laundering still worked with connectors such as `though`,
  `although`, and `yet`;
- exact-token strict matching missed natural unsupported paraphrases such as
  `Dead-letter routing is enabled by default for every Sable Queue.`;
- percentage matching for longer forbidden claims could still omit a central
  predicate, such as `emits`, while denial words such as `absent` could be read
  as positive assertions.

A parallel Grok xhigh audit also blocked the baseline on two related scorer
regressions:

- splitting on `, and` broke normal list claims such as `retry_class,
  next_attempt, and last_error`;
- `opt-in` was not a hard phrase anchor, so `Dead letters are automatic with
  --dead-letter...` could satisfy the positive opt-in claim while evading the
  forbidden automatic claim when the sentence omitted the entity name.

The scorer now keeps ordinary comma-and lists intact, treats `opt-in` as a
special phrase requirement, and uses page text as context only for trailing
entity anchors such as `in Sable Queue`. `must_not` matching requires every
forbidden-claim anchor to be present. Anchor matching allows only small lexical
variants and a few predicate aliases needed by the benchmark, such as
`automatic/default` and `emits/emit`. This remains a benchmark scoring aid, not
an ingester routing table.

Self-tests now include direct and full `score_case` regressions for a Trestle
`though` clause, the Sable Queue default-enabled paraphrase, `absent` as a
denial of automatic dead letters, the Pylon Graph `emits` predicate not being
replaceable by `describes`, Oxford-comma list preservation, `Nobody has agreed`
schedule denial, and compact Sable Queue automatic dead-letter prose.

## Result Summary

The baseline now has valid provider results for all ten MVP fixtures. Cases
`0001` to `0005` completed in the primary run. Cases `0006` to `0010` initially
failed because Grok Build usage balance was exhausted, confirmed by diagnostic
stderr showing HTTP `402 Payment Required`; after usage was restored, those
cases were rerun and all completed with provider exit code `0`.

Manual review found that the first heuristic scorer over-counted failures:
negative guardrail text such as "does not exist" was treated as an unsupported
positive claim, and cross-linked pages could be selected instead of the page in
the required category. The runner was updated to rescore existing snapshots,
prefer title/path matches in the expected category, ignore negated forbidden
claims, strip frontmatter from claim checks, and preserve numeric/code tokens
such as `127.0.0.1:7420`.

## Original Interpretation

The original final rescore showed that the then-current ingester passed all ten
MVP fixtures for `grok-4.6 medium`, but that result is superseded by the
hardened benchmark summary above. It remains useful as evidence that the first
scorer was too naive for negative guardrail prose and cross-linked pages.

The more important lesson is methodological: the benchmark scorer must be
reviewed with the generated pages before using it to justify a skill patch. The
first scorer and instructed sources did not justify changing
`skills/karpathy-wiki-ingest/SKILL.md` by themselves. The later hardened run
provided the concrete pressure scenarios used for the instruction patch.
