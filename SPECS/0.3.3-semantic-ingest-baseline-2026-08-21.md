# Semantic Ingest Baseline Runs, 2026-08-21

## Hardened Benchmark Summary

The original `10/10` run below is now treated as development-set evidence, not
as an acceptance-quality certificate. Two independent audits found that the
first fixture sources contained category-routing hints and that the scorer did
not enforce the deterministic gates described in the benchmark spec.

The benchmark was hardened in the same workstream:

- source files were de-instructed so category labels live in `expected.yaml`,
  not in `source.md`;
- `run_baseline.py --self-test` now covers negative controls for token-overlap
  false positives, concept dumps, under-split pages, silent hold no-ops, and
  seeded concept absorption;
- scorer output now includes deterministic gates for terminal status,
  manifest/source traceability, page validation, manifest validation, index
  rebuild, `type`/path consistency, idea metadata, and unknown categories;
- forbidden objects distinguish dump-page bans from specific unsupported-claim
  bans;
- the ingester skill received a minimal instruction patch for object inventory,
  lookup overproduction, and source/manifest discipline on every touched page.

Pressure scenarios that failed before the skill patch:

- `0003-query-lookup-floor`: the old skill created
  `concepts/retry-policy.md` and `entities/ambervault.md` alongside the desired
  query, so the lookup source overproduced supporting pages.
- `0009-merge-magnet-seeded`: the old skill updated
  `concepts/job-queues.md` with a see-also link but left `sources: []` and did
  not include that touched page in the raw manifest `referenced_by`.

## Result Summary

The baseline now has valid provider results for all ten MVP fixtures. Cases
`0001` to `0005` completed in the primary run. Cases `0006` to `0010` initially
failed because Grok Build usage balance was exhausted, confirmed by diagnostic
stderr showing HTTP `402 Payment Required`; after usage was restored, those
cases were rerun and all completed with provider exit code `0`.

Manual review found that the first heuristic scorer over-counted failures:
negative guardrail text such as "does not exist" was treated as an unsupported
positive claim, and cross-linked pages could be selected instead of the page in
the required category. The runner was updated to rescore existing snapshots,
prefer title/path matches in the expected category, ignore negated forbidden
claims, strip frontmatter from claim checks, and preserve numeric/code tokens
such as `127.0.0.1:7420`.

## Original Interpretation

The original final rescore showed that the then-current ingester passed all ten
MVP fixtures for `grok-4.6 medium`, but that result is superseded by the
hardened benchmark summary above. It remains useful as evidence that the first
scorer was too naive for negative guardrail prose and cross-linked pages.

The more important lesson is methodological: the benchmark scorer must be
reviewed with the generated pages before using it to justify a skill patch. The
first scorer and instructed sources did not justify changing
`skills/karpathy-wiki-ingest/SKILL.md` by themselves. The later hardened run
provided the concrete pressure scenarios used for the instruction patch.
