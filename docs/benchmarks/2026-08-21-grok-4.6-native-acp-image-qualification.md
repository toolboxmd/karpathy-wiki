# Grok 4.6 Medium native ACP image qualification

Date: 2026-08-21

## Decision

Use Grok 4.6 Medium as the recommended Grok profile for new general
mixed-media wikis, and deliver every explicitly declared JPEG or PNG as a
native ACP image content block in the same request as the normal ingester text.
Do not treat `read_file` or a prompt path as proof that Grok received visual
evidence.

This decision supersedes only the general mixed-media default. It does not
rewrite the [2026-08-20 text-ingest benchmark](2026-08-20-grok-4.5-vs-4.6-medium.md),
where Grok 4.5 Medium scored 95/100 and Grok 4.6 Medium scored 94/100. Grok 4.5
was the correct recommendation for that dated, text-oriented workload.

## Frozen vision result

The Naturbiss benchmark used 16 preselected images, including four known
failure canaries. Each run used an isolated working directory, the same
normalized image bytes, the same evidence-only prompt, and the same structured
output schema. Web access and subagents were disabled.

| Candidate | Valid | Required facts | Canaries | Semantic | Severe hallucinations | Median | Qualified |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| Grok 4.6 Medium, native ACP image | 16/16 | 100.0% | 4/4 | 160/160 | 0 | 27.619 s | yes |
| Grok 4.6 Medium, `read_file` | 16/16 | 88.9% | 2/4 | 151/160 | 1 | 28.171 s | no |
| Grok 4.5 Medium, `read_file` | 16/16 | 6.2% | 0/4 | 23/160 | 14 | 25.787 s | no |

The severe Grok 4.6 `read_file` failure described a D2C flowchart as a living
room. Grok 4.5 through the same path produced fourteen severe hallucinations.
Native Grok 4.6 recovered every frozen required fact and produced no severe
hallucination in the semantic review.

## Proven transport

Grok CLI 1.0.5 accepted the request through `--prompt-json`. The content block
array contained one text block followed by the image block:

```json
[
  {
    "type": "text",
    "text": "<normal ingester instructions>"
  },
  {
    "type": "image",
    "data": "<base64 image bytes>",
    "mimeType": "image/jpeg"
  }
]
```

The production adapter reuses these semantics. It detects JPEG and PNG from
file signatures, not from an arbitrary MIME claim or filename extension.
Primary image evidence is delivered first, followed by explicitly recorded
attachments in capture order. It does not scan the wiki or an evidence
directory for neighboring images.

Provider preflight canonicalizes every path and requires additional
attachments to remain within the primary evidence file's canonical directory.
A missing, unreadable, unsupported, escaped, or oversized declared image is an
actionable failure before provider launch. There is no automatic `read_file`
or path-only visual fallback. Text-only Grok ingestion retains its existing
prompt-file transport.

Normal invocation metadata excludes prompt JSON and base64. For audit it may
retain only the selected provider, model, effort, native transport marker,
content-block order, image MIME type, byte count, and SHA-256. Original images
remain under the normal wiki raw-evidence and manifest protocol.

## Repository canary

The implementation was exercised with one real Grok 4.6 Medium ingest in an
isolated disposable wiki. The provider completed successfully, the retained
metadata proved a text block plus one native JPEG block, the semantic page
identified the image-only menu state, and the raw file matched the submitted
SHA-256. The payload-free record is in
[the native ACP image acceptance evidence](../../tests/acceptance/grok/2026-08-21-native-acp-image.md).

## Limitation

The three-arm matrix did not test Grok 4.5 with native image input. It therefore
does not fully separate every model-by-transport interaction and does not prove
that Grok 4.6 is universally superior to Grok 4.5. The supported operational
conclusion is narrower:

- Grok 4.6 Medium with native ACP image transport is the only tested image
  configuration qualified for unattended canonical ingestion.
- Grok 4.6 remains viable for text ingestion.
- One Grok 4.6 Medium profile is therefore a reasonable default for a general
  mixed-media wiki.
- Both model selection and image transport matter.

The benchmark did not migrate a live wiki or runtime configuration. Its source
images and proprietary raw dataset remain outside this repository.
